> 2026-10-16 · 尚未开始实施。本文的勾选项表示实际完成和验证情况，不能根据设计描述预先勾选。
> 产品依据：[Agent 桌面呈现能力方案](foofoil-agent-desktop-terminal.md)。当前任务仅建立计划，没有实现应用功能。

## 1. 执行约定

后续 Agent 开始前读取当前用户要求、适用的 `AGENTS.md`、产品方案和本文；涉及兄弟仓库时再读取该仓库的指令。代码入口是当前源码中的参考位置，不要求机械照搬为新文件或新抽象。

- 按步骤依赖执行。一次推进一个可验证的交付单元，不跨越未通过的门槛。
- 每步完成后勾选真实完成项，并填写第 8 节交接记录。只有实现、测试、必要手工验证均通过，才能将步骤状态改为“完成”。
- 发现代码已被其他会话实现时，先核对行为及验证证据，再更新进度；不要重复实现或覆盖他人工作。
- 本文不授权自动提交、推送、创建 PR、删除用户数据或修改签名与沙盒权限。版本控制遵循仓库指令，使用 GitButler；不要为了勾选计划而制造空提交。
- 不为缺失验证编造通过结果。工具、签名或人工交互限制写入交接记录，标记“待验证”，其他独立工作可以继续。
- 需要调整方案时，记录具体原因和影响，并同步产品文档；不能通过降低验收要求掩盖失败。
- 应用代码变更按仓库要求构建、运行相关测试并执行 `./run`。文档改动不必启动应用。

## 2. 不变的产品边界

- 本地原文件直接引用；GUI 剪贴板文本／图片自动缓存并标记来源，缓存跟随历史及活动使用者释放。详见独立前置任务。
- 普通箔记录文件引用和展示状态；无痕箔不写历史、不参与重启恢复。Agent 临时展示复用无痕模式。
- Agent 只能只读展示已落盘文件，不创建可编辑便笺、不编辑内容、不写回文件。
- 原文件确认丢失时默认自动清理历史，用户可以关闭；权限失效和存储离线不得误删历史。
- Agent 首版支持自包含 Markdown、只读文本、图片和 SVG；不自动加载 Markdown 关联图片。
- `show` 新建，`update` 按稳定 ID 更新；更新不抢焦点、不覆盖用户布局、不重新显示隐藏窗口或重建已关闭窗口。
- 普通箔恢复为人工窗口，控制身份不跨应用运行恢复；不提供认领与自动重连。
- 首版不实现 MCP、远程桥接、文件监听、窗口组或 Agent Dashboard。

### S08：稳定窗口身份、归属与 Agent 只读模式

入口：`AppDelegate`、`FloatingWindowController`、`AppState`、`WindowConfig`、`Views/ReadOnlyTextView.swift` 和既有 Markdown 视图。

交付清单：

- [ ] 为自动化窗口建立本次应用运行内稳定的 `board_id`，与会轮换的内容 ID 分离。
- [ ] 用现有窗口集合加薄索引定位目标，关闭时清除映射，避免第二套生命周期管理。
- [ ] 保存运行期创建归属、修订号、普通／无痕属性；控制凭证不进入历史或持久窗口配置。
- [ ] `list` 只返回当前凭证获授权窗口；无权限请求不泄露其他窗口是否存在。
- [ ] GUI 替换内容立即解除 Agent 控制；移动、缩放、隐藏和置顶不解除。
- [ ] 普通箔重启／历史恢复为人工窗口，旧 ID／凭证不可继续使用；无痕箔不恢复。
- [ ] Agent 文本使用只读视图，菜单、快捷键、拖放及内部入口均不能意外进入可编辑便笺模式；复制和选择文字仍可用。
- [ ] Agent 接口仅接受受支持文件，不接收文本正文创建便笺，不提供写文件或编辑命令。
- [ ] 测试内容 ID 变化时 board_id 不变、关闭释放、越权、人工接管、重启失效及只读边界。

通过条件：窗口控制与内容历史身份解耦；不会借助现有 GUI 编辑路径绕过只读约束。

### S09：协议执行器与确定响应

交付清单：

- [ ] 按 S07 实现版本化请求／响应与输入校验，拒绝未知动作、不支持类型及超限输入。
- [ ] `show` 始终新建；`update`、`close` 仅操作指定授权 ID；`list` 不产生展示副作用。
- [ ] 四命令默认等待确定结果，区分接受与 ready；ready 不表示文件已经归档或像素已绘制。
- [ ] 实现限定作用域及期限的 request_id 去重；相同 ID 不同请求拒绝，重复请求复用结果而不重复执行。
- [ ] 已关闭窗口的旧 show 请求重试不重新创建；期限外重试行为遵循明确规格。
- [ ] 同一窗口操作按接受顺序串行提交，异步准备不能让旧更新覆盖新更新；关闭和取消纳入顺序规则。
- [ ] 实现 revision 和 expected_revision 冲突检查；失败或未提交请求不错误增加修订号。
- [ ] 内容准备后重新检查窗口存在、归属、暂停状态和修订条件，失败释放资源。
- [ ] 实现窗口数量、队列、创建频率与解码限制；拒绝时返回明确错误，防止无界任务。
- [ ] 实现错误码、超时、断连和取消；诊断不记录正文或凭证。
- [ ] 聚焦测试重复创建、超时后重试、并发逆序完成、关闭竞态、权限变化和资源释放。

通过条件：四命令结果确定且可解析，故障不会制造重复窗口、越权或无限排队。
