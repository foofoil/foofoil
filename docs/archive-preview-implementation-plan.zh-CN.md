# 压缩包预览分步骤实施计划

日期：2026-10-14；更新：2026-10-15

本文记录压缩包预览的产品约定、实施顺序和验收条件。当前为实施计划，尚未实现；各阶段完成后在清单中勾选，并记录实际验证结果。多格式、加密和分卷均属于计划范围，不因首阶段限制而永久排除。

## 一、产品约定

### 已确定的行为

- 复用侧边栏，树状展示压缩包内文件和目录；根目录也是可选择、可另存为的节点。
- 初始正文为空，显示“请选择要打开的文件”，不自动打开首项。
- 支持的文件在当前箔预览；包内文本只读，不允许编辑。
- 不支持的文件和目录在正文展示信息，并提供“另存为…”按钮。
- CUE、SACD ISO 和超过预览限额的文件不直接打开，展示信息并提示另存后打开。
- 内容自身的侧边栏不显示，压缩包文件树始终占用侧边栏；普通箔的导航行为保持原有语义。
- EPUB 已实现左右键切换上一章／下一章及对应菜单项；压缩包预览复用该能力，仍需完成场景集成验证。
- 用户界面采用“另存为…”；保存单文件、目录或根目录，分别实现单文件提取、目录提取和整包提取。
- 历史只记录压缩包，不记录包内打开的内容；不把原压缩包复制到缓存，只保留路径引用及必要访问授权。
- 压缩包历史缩略图仅使用固定图标，不生成包内内容拼图或截图。

### 本计划采用的默认行为

以下是实施默认值，区别于上述已确认约定；开发时若需调整，应同步更新本文。

- 从历史重新打开时回到初始提示，不恢复上次包内预览项。
- 包内嵌套压缩包先按文件信息展示，可另存为；递归浏览列入后续可选步骤。
- 首阶段不自动提取 HTML／Markdown 的关联资源、外部字幕或同目录封面。CUE 提示另存所在目录以保留配套音频。
- 文件“另存为”保存包内原始内容；目录保存该目录本身及子层级；根目录默认保存为压缩包同名文件夹。
- 提取到缓存的包内文件仅用于预览，关闭后在无读取者时清理；用户另存的文件不归缓存管理。
- 加密和分卷的支持按格式、算法和组合逐项声明，不能笼统声称所有 ZIP／7z／RAR 均兼容。

## 二、现有基础与实现边界

- `Views/NavigatorPanelView.swift` 已有树形节点、展开折叠和搜索展示基础。
- `PPTXArchive.swift` 已有 ZIP 中央目录、ZIP64、Store／Deflate、CRC 和路径检查，可作为普通 ZIP 后端的起点，但不是完整通用 ZIP 实现。
- `AppState+ContentOpen.swift` 已有各类内容的打开路由；现有打开过程会清空列表／导航并保存历史，不能直接用于包内预览而不调整上下文。
- 系统 libarchive 是多格式后端的首选验证对象。上游支持不等于目标 macOS 构建支持，必须验证实际 API、算法和样本。
- 采用应用内实现和随产品提供的能力，不引入用户可见的扩展安装或管理流程。

建议只建立实际需要的三个边界：归档后端负责条目枚举和提取；压缩包浏览状态负责原包、选择和任务；现有阅读器负责预览。不要为此建设通用虚拟文件系统。

历史身份必须属于原包，临时预览 URL 只属于派生内容。通过统一的预览上下文抑制包内历史写入、内容导航和编辑命令，覆盖普通打开、内置能力以及内容运行时的异步回调。

## 三、实施步骤

### 步骤 0：后端与样本验证

- [ ] 验证系统 libarchive 的 SDK 链接、C API 接入、最低支持系统和 Release 分发可用性，不依赖 Homebrew 或外部工具安装。
- [ ] 对 ZIP、TAR、TGZ、7z、RAR／RAR5 分别验证枚举、提取、取消、错误和文件名编码。
- [ ] 建立可复现样本：普通／固实、加密内容／加密文件名、各类分卷、空目录、中文名、同名条目、大文件、异常路径、损坏和缺卷。
- [ ] 明确只读支持矩阵：格式、压缩算法、加密算法、固实、分卷，以及库版本／系统版本。
- [ ] 对比系统库与精简内置库方案的实际 Release App 和 UDZO DMG 增量；确认许可证和第三方声明。

验收：输出实测矩阵及后端选择；某种能力不满足时列出替代方案和限制，不把无法验证的能力标记为支持。早期体积预算仅用于决策：系统库路线 DMG 约增加 0.1～0.5 MB、App 约增加 0.3～1 MB；最终以打包对比为准。

### 步骤 1：压缩包状态、打开路由和历史骨架

- [ ] 定义原包引用、访问书签、来源身份、条目身份、选中项、展开状态、提取任务和预览资源持有关系。
- [ ] 接入打开文件、拖放、剪贴板、共享和历史恢复；避免 EPUB／PPTX 等已有内容因底层是 ZIP 而被误路由为通用归档。
- [ ] 增加初始提示和文件信息正文：名称、类型、包内路径、可获得的压缩前后大小及原因。
- [ ] 历史只写原包；固定图标；包内选择、播放及阅读回调不得产生独立历史项或覆盖原包来源。
- [ ] 原包被移动、删除、修改或授权失效时明确反馈；源文件变化后使旧索引和缓存失效。
- [ ] 普通历史恢复回到初始提示；无痕压缩包不写历史、不参与重启恢复。

验收：原包不被复制进缓存；连续切换不同内容类型后历史仍只有压缩包，重启及缓存清空后的行为正确。

### 步骤 2：普通 ZIP／ZIP64 树形浏览

- [ ] 支持未加密、非分卷的 Store／Deflate ZIP 和 ZIP64；按条目元数据建树，不整包解压。
- [ ] 保留目录类型、空目录和根节点；补齐隐式父目录，避免仅以子节点数量判断目录。
- [ ] 处理 UTF-8、Unicode 扩展及历史文件名编码，无法确定编码时给出可预测行为。
- [ ] 条目身份不只依赖规范化路径；区分重复名称，并处理文件／目录冲突、大小写与 Unicode 规范化冲突。
- [ ] 将可枚举与可提取分离：存在不支持算法或加密条目时，不无条件拒绝可读取的整个目录。
- [ ] 支持选中、展开折叠、键盘操作、搜索及无障碍；搜索定位展开完整祖先链。
- [ ] 大量条目和深层目录有明确上限，避免主线程阻塞、递归溢出或每次全树重算。

验收：中文名、空目录、混合条目、数万条目与异常 ZIP 都得到正确展示或明确错误。

### 步骤 3：按需预览与 EPUB 无目录阅读

- [ ] 异步按需提取选中文件，保留扩展名；流式写入缓存，避免把大型压缩输入和完整输出同时放入内存。
- [ ] 复用图片、PDF、文本、CSV、SVG、网页、自包含文档和音视频预览；遵循既有类型支持边界。
- [ ] 只读文本：禁用编辑控件、编辑菜单、快捷键和自动保存路径。
- [ ] 不显示内容自身导航；禁用依赖包内文件列表的自动建组、轮播和播放队列行为。
- [x] EPUB 左右键切换上一章／下一章及对应菜单项已实现（2026-10-15 确认），无需在压缩包功能中重复开发。
- [ ] 在包内 EPUB 预览中复用并验证章节切换：隐藏内容目录后仍可逐章阅读；检查首末章节动作状态、输入焦点和压缩包文件树的键盘事件分配，沿用运行时的章节顺序定义。
- [ ] CUE、SACD ISO、嵌套归档和超限文件展示信息及另存引导；支持类型在提取后探测失败时也回到信息正文。
- [ ] 分类制定解压后大小、条目数、内存和提取工作量限额；固实包的小条目同样受工作量限制。
- [ ] 切换时取消旧任务，并以任务代次防止过期结果覆盖当前正文；媒体持续读取期间保护缓存。
- [ ] 关联资源缺失有明确说明，不默认扩大 WebKit 的文件访问范围或批量提取整个目录。

验收：混合内容连续切换不丢树、不写包内历史；文本无法编辑；普通与包内 EPUB 均可无目录逐章阅读；大文件及慢提取可取消。

### 步骤 4：文件、目录及根目录另存为

- [ ] 正文按钮、侧边栏上下文菜单和系统“另存为…”命令统一作用于当前选中项；未选中时禁用。
- [ ] 单文件保存原始字节；目录及根目录保存内部结构和空目录，并提供合理默认名称。
- [ ] 输出位置通过系统保存／目录选择交互授权；不静默覆盖目标，不改变原包。
- [ ] 防止绝对路径、父目录逃逸和链接绕过；首版不恢复符号链接、硬链接、可执行权限及其他特殊节点，明确说明跳过结果。
- [ ] 处理重名条目、大小写及规范化冲突；导出前或发生冲突时提供明确决策。
- [ ] 大文件流式输出；提供进度、取消和磁盘空间失败处理。文件先写自有临时输出，再提交为完整结果。
- [ ] 目录导出报告部分成功、跳过、失败和取消；只清理本次任务拥有的临时数据，不删除原有用户文件。
- [ ] 预览限额与导出限额分开，允许另存超过预览大小的文件，但仍保留工作量和资源控制。

验收：单文件、空目录、子目录及根目录导出结果正确；取消、磁盘不足和冲突不损坏既有文件；错误不显示为成功。

### 步骤 5：TAR 与压缩 TAR、单文件压缩流

- [ ] 增加 TAR／PAX 常见变体；扫描建索引并复用相同树、预览、历史和导出交互。
- [ ] 增加 TAR.GZ／TGZ，再按后端验证结果加入 TAR.BZ2、TAR.XZ；区分顺序扫描与随机定位成本。
- [ ] 增加单独 GZ／BZ2／XZ，作为单文件结果展示，确定无内置名称时的默认文件名。
- [ ] 选择重复扫描、有限缓存或中间 TAR 缓存策略；记录磁盘占用，不无界整包缓存。
- [ ] 对链接、稀疏文件和特殊节点制定支持范围，复用安全导出策略。

验收：完整目录枚举、后部条目提取及取消正确；首次扫描等待可见，后续访问不产生失控的磁盘或 CPU 消耗。

### 步骤 6：未加密单卷 7z、RAR／RAR5

- [ ] 增加经样本验证的未加密单卷 7z 和 RAR／RAR5；先覆盖普通压缩，再覆盖固实样本。
- [ ] 明确支持算法、字典和内存上限；避免为常见格式名称承诺全部算法。
- [ ] 固实包提取按解压块／工作量管理，重复选择采用有限缓存；慢任务可取消并可转为另存。
- [ ] 一个条目失败不清空目录；区分损坏、算法不支持、资源超限及提取失败。

验收：普通与固实样本均能正确预览或明确受限；导出大文件的内存占用可控。

### 步骤 7：加密支持

- [ ] 按步骤 0 结果依次加入 ZIP 的传统加密／AES，再加入 7z 与 RAR 的实际可支持加密组合；后端缺失能力时评估精简内置库或专项后端。
- [ ] 支持内容加密和文件名／目录加密两种流程：前者可先列树，后者解锁后才能列树。
- [ ] 密码输入支持取消和重试；区分错误密码、损坏、不支持的加密算法及无法确定原因，不伪造精确错误。
- [ ] 密码仅在必要的当前会话内持有，不写历史、日志、配置或缓存元数据；首版不保存到钥匙串。
- [ ] 预览与另存为共用解锁状态；关闭时清理解密后的应用缓存，遵循仍有读取者的资源生命周期。
- [ ] 重启恢复只恢复原包引用，重新请求密码；目录导出中明确部分条目使用不同密码的行为。

验收：正确／错误／取消密码、加密文件名、混合加密条目、历史恢复和缓存清理均可验证；文档准确列出支持组合。

### 步骤 8：分卷及加密分卷组合

- [ ] 分别验证并接入 ZIP 分卷、7z 的分段流、RAR 分卷命名与读取方式，不能仅靠拼接文件统一实现。
- [ ] 从任一卷打开时识别所属卷组和主卷；通过目录授权或多文件选择获取其余卷，避免依赖偶然的同目录访问权限。
- [ ] 验证卷顺序、缺卷、重复卷、错误卷及命名差异；提示用户定位缺失卷。
- [ ] 历史仍只有一个压缩包条目：记录主卷引用，必要时记录卷路径和访问书签作为来源元数据，不创建各卷历史、不复制各卷。
- [ ] 提取过程中跨卷读取可取消；修改、移动或替换任一卷后使相关索引／缓存失效。
- [ ] 验证加密＋分卷、固实＋分卷以及三者组合；分开声明哪些组合可列目录、可预览和可完整导出。

验收：完整卷组成功；缺卷和错误卷明确反馈；重启后授权可恢复；组合样本通过且不会留下伪完整输出。

### 步骤 9：收尾、文档与发布验证

- [ ] 检查菜单、快捷键、只读、无痕、多窗口、窗口关闭、缓存回收和历史图标一致性。
- [ ] 更新中英文 `SupportedContent.md`、快捷键概览、必要 README 和本地化字符串；披露格式及组合限制。
- [ ] 添加有意义的后端、路径、导出、历史隔离和异步切换回归测试；进行树操作和保存对话框人工检查。
- [ ] 在支持的 macOS 上构建和运行相关测试；检查新警告、Release 签名与公证流程。
- [ ] 测量 Release App、最终 DMG 增量以及预览缓存峰值；分别报告，不把运行缓存算成安装体积。
- [ ] 完成代码修改后运行 `./run`，让用户直接检查最终交互。

验收：阶段支持矩阵与用户文档一致；无未说明的回退或依赖；打包、测试和人工验证结果记录完整。

## 四、可选后续步骤

- 关联资源提取：按引用或受限目录提取 HTML／Markdown 资源、字幕与封面，单独验证读取范围和缓存上限。
- 嵌套归档浏览：增加返回上层与独立容器身份，设置递归深度、累计输出和总工作量限制，历史仍归最外层原包。
