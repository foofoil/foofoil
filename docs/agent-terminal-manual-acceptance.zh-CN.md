## 2. CLI 与基础闭环

```sh
fa show "$QA/含 空格/验收.txt" --title 'QA 文本 A' --caller 'QA Agent A' --request-id qa-show-a --json
fa list --json
# 复制上一步 board_id 后执行：
fa update BOARD_A "$QA/report.md" --expected-revision 1 --request-id qa-update-a --json
fa close BOARD_A --expected-revision 2 --request-id qa-close-a --json
```

- [ ] `--version` 和 `--help` 可用，帮助中的四命令、参数与实际行为一致。
- [ ] show 成功只创建一个目标窗口，返回 `status=ready`、非空 `board_id`、revision 1。
- [ ] 同文件用不同 request_id 再 show，创建独立窗口；show 不复用已有窗口。
- [ ] list 返回该会话的窗口，包含可用于后续操作的 ID 与修订信息。
- [ ] update 保持 board_id，成功 revision 增加 1，内容更新到指定文件。
- [ ] close 关闭指定窗口，返回关闭前 revision；随后 list 不再包含它。
- [ ] 再次以新的 request_id 更新或关闭已关闭 ID，返回 `BOARD_NOT_FOUND`，不重建窗口。
- [ ] 四命令有无 `--json` 都输出可解析 JSON；失败退出非零，stderr 给出错误码，stdout 没有夹杂日志。
- [ ] 中文、空格、长路径、相对路径可用；相对路径按调用终端当前目录解析。
- [ ] 缺少参数、未知选项、错误 revision 格式、错误 app 路径均明确失败，不打开意外窗口。
- [ ] title 与 caller 正确显示；update 不能借助参数更改 title 或 incognito。

每节会创建多个窗口。普通功能测试保持低于每分钟 12 次成功 show，及时关闭本节窗口；限额测试放到第 10 节单独执行。

## 3. 内容与只读展示

- [ ] UTF-8 中文、英文、emoji、换行、制表符显示正确；空文本可以打开且仍为只读。
- [ ] 代码文件通过只读文本通道展示，无编辑或写回入口；不以是否语法高亮作为必需条件。
- [ ] Markdown 标题、列表、表格、代码块、中文和较长文档显示合理，无明显截断或乱码。
- [ ] 文本/代码/Markdown 可选择和复制；尝试输入、粘贴、退格均不能改变正文或源文件。
- [ ] Markdown 切到源码展示后仍只读；关闭再恢复后仍遵守只读策略。
- [ ] PNG/JPEG/HEIC/TIFF/WebP/BMP 按支持范围打开；透明区域、方向、尺寸比例合理。
- [ ] 动画 GIF 展示首帧，不要求动画播放；大图缩放和拖动正常。
- [ ] SVG 正常展示；纯 viewBox、显式宽高等合法尺寸场景按协议验证。
- [ ] Markdown 的相对路径图片、绝对路径图片和 HTTP 图片不自动加载；标准图片语法出现本地化不可用提示，响应含 `MARKDOWN_RESOURCES_BLOCKED`。
- [ ] Markdown 内嵌 HTML 图片也不加载；不把原始 HTML 的具体提示位置作为固定排版要求。
- [ ] SVG 内脚本不执行，外部图片、字体及其他外部资源不自动加载。
- [ ] 若核验网络资源阻断，用自有本地 HTTP 测试服务观察请求，先确认服务可用，再检查展示期间无资源请求。视觉上没有图片不能单独证明没有请求；本地文件零读取需结合受控跟踪或自动测试证据。
- [ ] PDF、HTML、网页 URL、音视频、目录、压缩包拒绝；不会改走普通 GUI 预览、下载或展开。
- [ ] 不可读/不存在文件、损坏图片、无效 UTF-8、含 NUL 文本、损坏 SVG、带 DTD/实体的 SVG 明确失败。
- [ ] 超过 2 MiB 的文本/Markdown/SVG、超过 16 MiB 的输入、超像素或边长的图片被拒绝；没有内存暴涨或界面卡死。
- [ ] title/caller/request_id 按 UTF-8 字节限制处理，超限明确失败；多字节中文也覆盖边界。

注意：ready 表示协议规定的读取、校验和提交完成；Markdown 排版和 SVG 绘制可能稍后完成，不将响应到达瞬间尚未绘制判为失败。内容未出现、长时间空白或显示错误应记录失败。

## 4. 显式更新与失败保留

- [ ] 原文件原位修改后，不发 update 时画面不自动刷新；发 update 后显示新内容。
- [ ] 将另一个文件原子替换到同一路径，再 update，显示替换后的内容，不复用旧缓存。
- [ ] 同路径图片与 SVG 更新可见，不能只测试换文件名。
- [ ] 同一源文件创建两个窗口，只更新其中一个时另一个保持自己的当前画面。
- [ ] update 指向不存在、损坏、不支持或超限文件时失败，旧窗口和旧内存画面保留，revision 不增加。
- [ ] 失败后改用合法文件 update，仍可成功，没有锁死或残留加载遮罩。
- [ ] 文本→Markdown→图片→SVG→文本跨类型更新正确，board_id 保持不变。
- [ ] 更新前用户重命名窗口，更新后用户标题保留。
- [ ] 不将保留旧画面理解为保留旧源文件：退出后若源文件已删除或被覆盖，不要求恢复被删除的旧正文。

## 5. 窗口、阅读位置与人工接管

每种内容至少检查一次；跨类型更新重点检查极小图片窗口变成文本的场景。

- [ ] 移动、调整尺寸、置顶、透明度、边框开关后 update，位置和实际宽高保持，不跳回默认值。
- [ ] 同类型更新保留内容缩放与阅读位置；内容变短后滚动位置合理收敛，不留下永久空白。
- [ ] 图片换路径但仍为同类内容时保留阅读状态；跨类型更新重置内容缩放/阅读位置，保留窗口布局。
- [ ] 小至约 80×80 的窗口跨类型更新不被强行扩窗；文本不会因窄小窗口彻底消失。
- [ ] 边框与阴影实际显示符合用户选择，跨类型更新不出现状态与画面不一致。
- [ ] 隐藏窗口/隐藏应用后 update，不解除隐藏、不闪现；隐藏时 list、close 正常。
- [ ] 更新不激活窗口、不抢键盘焦点、不打断在其他应用中的连续输入。
- [ ] 多个窗口分别 update/close，只影响指定目标。
- [ ] 移动、缩放、置顶、透明度、边框、标题操作后 Agent 仍可控制。
- [ ] GUI 替换内容、重置或拖入新内容后解除 Agent 归属；旧 ID update/close 返回 `BOARD_NOT_FOUND`。
- [ ] 拖入新内容期间不出现可编辑旧正文；成功替换后按普通 GUI 内容规则工作。
- [ ] GUI 手动关闭目标后，后续或在途 update 不得重建它。
- [ ] 箔片信息能找到 Agent 创建来源和 caller，正文区域不增加持续占用空间的控制栏。

## 6. 冷启动、隐藏、多屏与 Space

先在 GUI 中退出指定测试构建，再从 CLI 冷启动。不要用会重新打开应用的自动化选择操作来判断是否额外开窗。

- [ ] 分别将普通启动行为设为“新建窗口”“恢复窗口”“不打开窗口”（以实际设置项为准），每次退出后用 show 冷启动：只出现请求窗口，无额外空窗或整批历史恢复。
- [ ] 应用未运行时执行 list，不出现额外空白内容窗口或历史批量恢复。
- [ ] 已运行/已隐藏时连续 show、list、update、close，隐藏与前台应用状态符合约定。
- [ ] 在 TextEdit 等应用连续输入，同时从另一终端触发请求；输入没有落入 foofoil 或丢失焦点。
- [ ] 单屏下跨桌面、目标窗口在另一 Space、前台应用全屏时请求，不强制切换 Space。
- [ ] 双屏下分别在主屏/副屏放置窗口，更新不移屏、不改变坐标和尺寸。
- [ ] 不同缩放倍率显示器之间移动后更新，布局与内容清晰度合理。
- [ ] 显示器断开/重新连接后，不出现完全无法找回的窗口；按现有窗口恢复规则处理可用区域。
- [ ] 以上场景记录屏幕录像或前台应用观察；只采样一次进程名不能证明连续输入未受影响。

缺少副屏或全屏环境的项目记环境阻塞，不勾选通过。

## 7. 授权、隔离与控制开关

- [ ] fa 与 fb 各 show 一个窗口；各自 list 只列自己的窗口，不泄露人工窗口或另一会话内容。
- [ ] fb 操作 fa 的 board 返回 `BOARD_NOT_FOUND`；与随机未知 ID 的错误一致。
- [ ] 两会话使用相同 caller 名称，仍相互隔离；同一 session 更改 caller 不产生新的安全身份。
- [ ] 默认 session 被多个 CLI 调用共享；需要隔离时确实使用不同 `--session` 文件。
- [ ] session 文件为当前用户的私有普通文件，权限正确；过宽权限、其他所有者或不合规文件明确拒绝，无 secret 日志。
- [ ] 设置→通用→Agent 控制：中文、英文说明清楚，开关可操作。
- [ ] 暂停后 show/update/close 返回 `CONTROL_PAUSED`；list 仍可用，人工窗口操作仍可用。
- [ ] 恢复控制后新请求成功；暂停时失败的旧请求不会自动补执行。
- [ ] 撤销会话后窗口保留并转为人工控制；原会话在本次运行被拒绝，不能继续 update/close。
- [ ] 撤销后 CLI 不自动创建新 secret 绕过撤销；不以换 session 或 show 作为错误恢复手段。
- [ ] 退出重启后按新的 run_id 建立授权，旧 board_id 无效；暂停/撤销状态不作为跨运行设置恢复。

## 8. revision、去重与并发

- [ ] 使用当前 revision update 成功；使用旧 revision 返回 `REVISION_CONFLICT`，内容与 revision 不变。
- [ ] close 携带旧 revision 同样冲突，窗口保留；正确 revision 可关闭。
- [ ] 600 秒内完全相同的 show/request_id 重试，返回相同 ID/revision，只存在一个窗口。
- [ ] 同 request_id 改 path/title/action 等请求参数，返回 `REQUEST_ID_CONFLICT`。
- [ ] 相同 update 重试只增加一次 revision；相同 close 重试返回原结果。
- [ ] 窗口关闭后重试原来的 show，返回原结果但不重建窗口。
- [ ] 两个不同请求同时以相同 expected_revision 更新一个窗口：只一个成功，另一个冲突，最终 revision 只增加一次。
- [ ] 并发操作不同窗口，结果对应各自 ID，没有串窗或错误复用。
- [ ] 并发首次使用同一个 session，不损坏凭证、不创建不一致身份。
- [ ] 在途同 ID 重复请求得到一致结果；不要在请求处理中更改夹具内容来混淆读取时点。

应用按“接受顺序”执行 FIFO，终端启动先后不能证明接受顺序。要判定严格 FIFO，须有受控慢读取或接受顺序跟踪。600 秒之外同 ID 可能作为新请求处理，不把超期重试当作无副作用操作。

## 9. 在途取消、超时与竞争

这组需要受控慢准备条件或测试辅助设施。普通小文件无法稳定复现时，标记待测并引用自动测试证据，不能据此勾选手动通过；不要用设备强制拔除、全局挂起或破坏用户目录制造阻塞。

- [ ] 内容准备期间人工关闭窗口，旧请求不得提交或重建窗口。
- [ ] 内容准备期间 GUI 替换内容，旧请求不得覆盖人工新内容。
- [ ] 内容准备期间暂停，再恢复，旧请求不得趁恢复后提交。
- [ ] 内容准备期间撤销会话，旧请求不得提交。
- [ ] 已接受请求超过应用 30 秒期限返回 `TIMEOUT`；阻塞读取返回后不得迟到提交。
- [ ] 慢读取期间传输仍可发出超时响应，没有无限排队或持续增加准备任务。
- [ ] 终止 CLI 不导致应用崩溃；已接受的操作可能已执行，使用原 request_id 在有效期内查询/重试结果。
- [ ] 命令超时后不盲目换 ID show；检查 list，并按同 ID、同参数规则重试。
- [ ] 应用退出时未完成请求明确失败/超时，重启后不恢复旧控制任务。

## 10. 限额与长时间运行

在独立测试运行中执行并保留各请求输出；不要把瞬时高负载失败与功能错误混为一谈。

- [ ] 60 秒内第 13 次成功创建尝试触发 `RATE_LIMITED`，未额外创建窗口；窗口关闭不应绕过该创建频率限制。
- [ ] 按频率限制分批保留至 32 个自动化窗口，再创建触发 `WINDOW_LIMIT`；关闭自己的一个后可继续创建。
- [ ] 并发队列饱和时出现协议规定的拒绝/超时，队列与内存有界，恢复负载后可继续正常操作。
- [ ] 32 个会话上限包含本次运行已撤销的身份；需要重新测试时清理本轮窗口并重启独立测试进程。
- [ ] 同 ID 等待者上限、去重账本容量与请求信封边界，需要辅助设施时单独记录协议测试结果，不伪装成普通 CLI 可直接构造的手动测试。
- [ ] 单窗口连续更新至少 60 次，内容和 revision 对应，无新增窗口、明显闪烁或阅读位置漂移。
- [ ] 文本、Markdown、图片、SVG 分别持续更新 15—30 分钟，记录开始/稳定期/结束内存、CPU、响应耗时与窗口数。
- [ ] 停止更新后资源占用能稳定；关闭窗口后无持续任务增长或明显泄漏趋势。
- [ ] 快速更新长 Markdown 不堆积渲染任务；界面仍可拖动、关闭和进入设置。
- [ ] 连续读取失败与超限请求不会让应用陷入高 CPU 或不可恢复状态。

短时间几十次更新的内存样本只作为局部证据，不替代长期运行曲线；暂不设未经产品确认的机器无关毫秒阈值。

## 11. 历史、恢复与文件生命周期

- [ ] 普通 show 进入历史；多次 update 不按每次更新新增历史版本，当前引用与内容类型正确。
- [ ] incognito show 不进入历史，不参与退出后的窗口恢复。
- [ ] 普通 Agent 窗口退出再恢复为人工窗口，旧 Agent ID 失效；只读展示和 Markdown 资源限制仍保留。
- [ ] 恢复后边框偏好保留；GUI 明确替换内容后解除原只读展示策略。
- [ ] CLI 退出不关闭已经创建的窗口；窗口生命周期不依赖原 CLI 进程存活。
- [ ] 删除测试历史记录不删除原文件；继续更新不会意外复活已删除的历史记录。
- [ ] 同一源文件多个窗口按已有历史去重规则工作，不要求强制生成每窗独立历史条目。
- [ ] 原文件同卷重命名/移动后，普通历史恢复按书签能力定位；用已经不存在的旧路径 update 明确失败。
- [ ] 删除源文件、实际失去读取权限或所在卷离线后，恢复给出合理不可用状态，不以持久正文副本冒充成功。
- [ ] 正在显示时源文件失效，已有内存画面可保留；下一次失败 update 不破坏画面。
