# ⌘P 接入 Spotlight 文件搜索实施计划

日期：2026-09-23  
状态：第一版已实现，采用授权文件夹搜索；验证记录见第 11 节。

## 1. 目标与范围

在现有 ⌘P 搜索面板中增加本机文件名搜索，让用户能够找到并在浮箔中打开尚未进入历史记录的文件。复用 macOS Spotlight 索引，不扫描全盘，不建立第二套文件索引，不增加第三方依赖。

第一版包含：

- 历史记录搜索与本机文件名搜索并行，历史记录优先展示。
- 保留历史库已有的正文、OCR 等搜索行为；新增的 Spotlight 来源只匹配文件名。
- 文件结果按浮箔及当前可用扩展的打开能力过滤。
- 合并结果、跨来源去重、键盘选择、回车打开和失败提示。
- 保留现有网址输入行为；独立 `.url` 模式不启动 Spotlight 查询。

第一版不包含：Spotlight 正文搜索、应用启动器、系统动作、自然语言搜索、联网搜索、全盘遍历兜底、主动下载云端文件、拼音或自建模糊索引。无需将浮箔历史写入 Core Spotlight。

## 3. 前置验证：沙盒与可见范围

工程主应用 Debug 和 Release 均设置 `ENABLE_APP_SANDBOX = YES`。工程设置的用户选择文件权限为只读，但现有 entitlements 文件另声明了用户选择文件读写权限；本次不修改任何权限声明。不得把设置 `searchScopes` 理解为授予文件访问权限，也不得把终端 `mdfind` 的结果当作沙盒应用的结果。

先在真实签名、开启沙盒的应用进程中做最小验证，记录系统版本、构建配置、目录权限状态、查询是否启动、命中文件和实际打开结果：

1. 查询用户主目录范围，对比容器内、已授权目录内、未授权目录内的已索引测试文件。
2. 使用 `NSOpenPanel` 授权一个测试目录，再以该目录 URL 为 scope 查询；验证重启后的 security-scoped bookmark 恢复。
3. 对照未索引目录、Spotlight 排除目录、已删除文件和 iCloud 占位文件。
4. Debug 与 Release 均验证，不能仅验证命令行工具或关闭沙盒的测试程序。

产品默认目标是用户主目录内系统允许返回的文件；第一版不自动搜索外置卷和网络卷，授权方案只查询用户明确选择的范围。最终可用范围以验证结果为准：

- 若主目录查询可用，采用该范围；打开未授权文件时仍须单独处理权限。
- 若可靠搜索需要目录授权，提供“选择搜索文件夹”入口，用系统文件夹选择器取得只读访问并保存书签；仅查询用户选择的目录。界面说明实际范围，不能声称已搜索整台 Mac。
- 若授权目录内的已索引文件仍无法可靠查询，暂停该来源的正式接入，记录复现和限制；历史搜索继续可用。

目录授权分支只在前置验证证明必要时实现。书签属于设置数据，可放在现有设置体系中，不另建数据库；提供移除目录入口，停止使用对应授权。过期书签按系统返回状态刷新，无法恢复时提示重新选择。查询与打开期间的 security-scoped access 必须配对释放，媒体播放所需访问交由既有生命周期接管。

本计划不通过关闭沙盒、增加宽泛 entitlement、申请完全磁盘访问或运行外部 `mdfind` 绕开约束。

## 4. 查询规则与生命周期

使用 Foundation `NSMetadataQuery`，设置显式 scope 和文件名谓词；查询值通过谓词参数传入，不将用户文本拼接进谓词格式。

- 对输入去除首尾空白；空输入不查询，单个中文字符也可查询。
- 仅匹配 `kMDItemFSName`，按字面子串处理，忽略大小写；变音符号行为在系统谓词上验证后固定。`*`、`?`、引号和反斜杠不得成为用户可注入的查询语法。
- 排除目录、应用包、隐藏项及浮箔自有缓存；其他包类型按现有打开能力判断，不笼统排除文档包。
- 搜索阶段只读取必要元数据，不读取文件正文，不启动扩展进程做内容探测，不生成新缩略图。
- 从现有宿主与可用扩展能力中获得轻量类型候选过滤规则；真正打开时再走完整 `canOpenFile` / provider 解析，避免维护第二份硬编码格式表。

保留现有 150 ms 防抖，历史查询和 Spotlight 查询互不等待。每轮使用 generation 标记；任何旧查询通知和旧任务结果都必须丢弃。

服务在有运行循环的受控执行上下文管理查询及通知；不得把 `NSMetadataQuery` 或 `NSMetadataItem` 直接跨 actor 传递。先提取为不可变、可发送的值，再进行后台过滤和排序；AppKit 与 UI 更新仍在主线程。禁止主线程大批量文件 I/O。

第一版采用单次收集：初次 gathering 完成后提取结果并停止，不保持长期 live query。观察者在开始前安装，提取时遵循 query 的更新控制要求。输入变化、切换模式、清空、关闭或失焦隐藏面板时停止查询、移除观察者并取消超时任务。

初始参数：Spotlight 显示上限 20 项，最多处理 200 个元数据候选，3 秒未完成则停止本轮并显示可重试状态。这些是实现参数，须通过实测调整。候选先用查询支持的稳定排序收集，再做本地相关度排序；只承诺候选集内排序，不承诺全盘最优结果。应用层截断不等于限制系统查询成本，须单独验证宽泛单字查询。

## 5. 合并、排序与选择

UI 层定义统一候选（例如 `SearchItem`）：历史记录、文件、打开网址三种情况。文件候选包含稳定 ID、URL、文件名、父目录、轻量类型信息和可用的修改时间。来源标识不能复用历史 UUID。

展示顺序固定为“历史记录 → 本机文件 → 打开网址”。历史记录保持当前排序；文件按完整文件名匹配、去扩展名匹配、前缀匹配、子串匹配排序，同级按修改时间降序、文件名和路径稳定排序。

去重规则：

1. 对文件 URL 标准化后比较；不能无条件小写路径，须兼容大小写敏感卷。
2. 在已有访问权限且成本可控时，可用文件资源标识辅助识别同一文件；不能为了去重遍历目录或请求权限。
3. 历史结果对应的真实外部源文件与文件候选相同时，保留历史行。不同历史记录之间沿用原有语义，不擅自折叠。
4. 当前历史搜索结果没有源 URL 字段，需从对应 `WindowConfig` 中提取可确认的外部文件身份；必要时扩充历史查询投影。不要逐行同步读取数据库或解析大量书签。
5. 历史缓存副本、原文件和同名不同路径文件不是当然相同。无法证明身份时保留两项，并通过路径区分；第一版不为此新增内容哈希或历史库迁移。

内部选择以稳定 ID 保存，显示时映射到扁平候选索引。分组标题和状态行不可选。每次新输入默认选择第一项；同轮异步结果补齐时保留用户已移动的选择，选中项消失才回退到相邻有效项。上下键、Control-N/P、回车与中文输入法组合输入保持现有行为，并确保选中行滚入可见区域。

## 6. 打开与错误处理

历史项继续调用 `openSearchResultInNewWindow(id:)`。文件项新增 URL 回调，通过 `AppDelegate` 复用 `openGroupedFiles` 的类型分组和宿主/扩展打开路径：优先使用空白浮箔，否则新建，避免覆盖已有内容。网址沿用当前入口。

打开前重新检查文件可用性及权限。Spotlight 返回普通 URL 不代表具有安全范围授权；不能仅凭一次 `fileExists` 返回 false 就断言文件已删除。

- 已有访问权限：直接打开，按现有规则进入历史记录。
- 缺少权限：经系统 `NSOpenPanel` 让用户选择目标文件，或恢复已有有效书签；选择其他文件时按实际选择处理，取消则保留面板与查询。
- 文件已移走、类型不可打开或打开失败：本地化说明原因，保留查询便于继续选择，不制造空历史记录。
- 云端未下载文件：不在搜索时触发下载；明确提示可用性，后续处理由现有打开流程决定。

应能区分打开流程已接受和明确失败，不能在发起回调时就无条件关闭面板。成功接受打开后关闭并停止查询。若现有打开入口缺少结果反馈，增加最小必要的返回值或回调，不重构整个内容加载架构。

文件结果仅提供打开操作，不套用历史项的“删除”菜单，更不能删除磁盘文件。

## 7. 界面与状态

沿用面板材质、尺寸、焦点和位置逻辑。⌘P 入口和占位文案应说明“搜索历史与文件”；独立网址输入模式保持现有文案。文件行展示名称、类型图标和父目录，完整路径可通过帮助文本提供。

分别管理历史与文件来源的加载状态。历史结果先返回即可操作；Spotlight 超时或不可用不影响历史结果。仅在两个来源都结束且无结果时显示整体空态。不得将正常零结果直接解释为索引损坏或权限不足；只有获得明确证据时才显示具体原因，否则说明当前搜索范围内未找到。

关闭路径必须统一收口：当前 Esc、⌘W、`dismiss()` 和 `windowDidResignKey` 都存在直接 `orderOut`，实施时一并调用模型停止方法。授权面板导致失焦时保留输入和待打开上下文，取消后能恢复搜索面板。

新增分组、加载、失败、权限和无障碍文案全部写入 `Localizable.xcstrings`，补齐中英文；验证深浅色和 VoiceOver 标签。

## 8. 实施顺序

1. **验证平台边界**：完成沙盒矩阵，记录证据，确定主目录或授权目录方案。
2. **实现查询服务**：完成谓词、scope、取消、超时、元数据值转换和有限结果处理。
3. **接入模型**：加入统一候选、两个来源状态、排序去重与稳定选择；保留历史和网址行为。
4. **接入 UI 和打开流程**：完成分组、文件行、权限分支、关闭清理及本地化。
5. **验证与交付**：完成针对性测试、真实索引手工验收、构建和运行，记录限制。

各阶段不引入通用插件搜索框架、后台常驻索引服务或无实际需求的 provider 协议层。需要可控异步测试时，使用最小依赖注入即可。

## 9. 验收标准

自动化测试不依赖开发机 Spotlight 索引；用固定候选和可控异步返回验证以下行为：

- 文件名匹配与特殊字符处理、类型过滤、稳定排序、上限与去重；同名不同路径不误合并。
- 历史先返回、文件先返回、快速改词、取消后晚到回调、超时和单来源失败。
- 新结果到达不改变用户已选目标；分组标题不可选；删除历史后索引仍有效。
- 空输入与 `.url` 模式不查询文件；关闭面板后没有存活查询和观察者。
- 文件项不能调用历史删除；权限取消、打开失败不记录成功历史。

真实签名应用手工验收：

| 场景 | 预期 |
| --- | --- |
| 未曾打开、已索引、受支持的文件 | 能按名称找到，经授权后在浮箔打开 |
| 同一外部文件命中历史与文件来源 | 只显示历史行；无法确认身份的副本不误去重 |
| 名称相同、目录不同 | 路径可区分，分别打开正确文件 |
| 中文、空格、引号、`*`、长文件名 | 字面匹配稳定，无谓词异常 |
| 未授权或已撤销权限 | 不绕过权限、不误报删除，授权取消可恢复 |
| 未索引、被排除、已移走或云端占位文件 | 结果和失败提示符合实际，不自动扫描或下载 |
| 查询中 Esc、⌘W、失焦、再次 ⌘P | 无旧结果闪回，无持续查询；授权失焦可恢复 |
| 多结果键盘导航及中文输入法 | 选中项可见，组合输入期间回车不误打开 |
| Spotlight 慢或不可用 | 历史与网址继续可用，加载状态最终结束 |

性能以代表性用户目录实测记录：连续输入时无可见卡顿，查询数始终不超过一条活动 Spotlight 查询，面板关闭后恢复空闲。报告首批历史和文件结果耗时、宽泛查询峰值内存与 CPU；不把系统索引延迟算作可保证的固定响应时间。

代码实施完成后从应用仓库根目录执行相关测试，并执行 `xcodebuild test -project foofoil.xcodeproj -scheme foofoil -destination 'platform=macOS'`。新增警告须处理；最后执行 `./run` 构建并启动，完成上述交互验收。本文档提交本身无需构建或启动应用。

## 11. 第一版实施记录（2026-09-23）

### 已落实

- 新增 `SpotlightFileSearch`，使用系统元数据查询和用户授权文件夹的显式路径范围，150 ms 防抖、3 秒超时、最多读取 200 个候选、展示 20 个文件。
- 历史查询投影携带已有 `source_fingerprint` 中的文件路径，用于跨来源去重，无数据库结构迁移。历史缓存有明确原文件来源标识时可去重，不能确认来源的副本保留。
- ⌘P 显示历史与“所选文件夹中的文件”分组，保持键盘选择身份，支持自动滚动；网址专用模式不查文件。
- 使用现有宿主文本扩展名集合及可用 provider 声明做轻量过滤，文件行仅展示图标、名称和目录。
- 打开时检查可读性，权限不足交由系统文件选择器；缺失文件与云端未下载文件分别处理。`openGroupedFiles` 返回是否已接受打开请求，复用空白浮箔或新建窗口。
- 统一关闭查询；旧查询通知、超时任务和历史异步结果均受 generation 保护。中文输入法组合输入交回系统处理。
- 文件候选没有删除菜单，搜索不创建历史记录。新增文案包含中英文。

### 平台验证证据与最终决策

本机 macOS 27.0（26A428），使用临时 App bundle、有效 Apple Development 签名和应用现有沙盒 entitlements 运行 Debug 式与 `-O` 查询探针，并在真实 Release 应用中检查路径：

- `NSMetadataQueryUserHomeScope` 和 Foundation 主目录 API 在该沙盒中指向容器，查询 `README` 为零项。
- 经 `getpwuid(getuid())` 取得账户目录，作为 URL scope 后返回 109 项。但进一步检查发现这些项目来自 `/Library` 等范围外目录，不能作为主目录搜索可用的证据。
- 改为字符串路径 scope 后，未授权主目录返回零项。因此最终实现采用文档第 3 节的授权文件夹分支，移除账户主目录查询。
- 普通本地元数据项通过 `kMDItemPath` 提取路径；探针中的 `NSMetadataItemURLKey` 没有返回这些文件的 URL。

最终实现由系统文件夹选择器授权，保存只读安全范围书签；每轮查询解析书签并配对释放访问，打开文件时重新持有目录访问。过期书签刷新，无法恢复则提示重新选择；“移除搜索文件夹”删除应用保存的授权引用。未配置范围时不启动查询。

服务向 `searchScopes` 传入明确的路径字符串，并额外校验每个结果在所选目录之下（区分大小写，不误包含同前缀的相邻目录）。新增字面文件名复核，避免系统查询语法将通配字符扩展成错误结果。

### 验证范围与限制

## 14. 固定主目录范围与浮箔总览接入（2026-09-24）

### 决定与依据

搜索范围不再由用户挑选任意文件夹，固定为当前用户主目录（`/Users/<用户>`）。沙盒只把文件访问授予用户明确选择的路径：用与 App 相同 entitlements 的签名探针实测，未授权时主目录字符串 scope、`NSMetadataQueryUserHomeScope`、全盘 scope 都返回 0 项，主目录文件也不可读；因此保留一次系统面板确认，但只接受用户主目录，不保存其他目录。

- 未授权时不启动查询；⌘P 与浮箔总览各提供一个“开启文件搜索…”入口，点击后由系统文件面板确认主目录。
- 授权书签失效时自动清除并回到未授权状态，界面提示重新开启。
- 不新增 entitlement、不申请完全磁盘访问、不关闭沙盒；`NSHomeDirectory`/`homeDirectoryForCurrentUser` 在沙盒里指向应用容器，账户主目录改用 `getpwuid` 取得。

### 实现

- `SpotlightSearchFolders` 替换为 `SpotlightSearchAccess`：保存单个主目录只读安全范围书签，`beginAccess` 解析并持有访问，失效即清除；`SpotlightSearchAuthorization` 负责系统面板确认，选择非主目录不保存并提示重新选择。
- 新增 `SpotlightFileOpener`：打开前的可读性检查、文件级安全范围 URL、装载期间的目录授权保持；⌘P 与浮箔总览共用同一套打开流程。
- 查询服务增加 `start(text:completion:)` 便捷入口（宿主与可用扩展类型 + 已授权范围），并在主目录范围下排除 `~/Library`：应用数据与缓存数量庞大，不属于用户文件。
- 浮箔总览搜索：关键字非空时才查询并呈现“主目录中的文件”结果区，出现用透明度与位移过渡（0.3 s），结果更新用平滑过渡（0.25 s）；文件行展示类型图标、名称与父目录，点击打开。
- 浮箔总览打开文件前先检查可读性：可读则让覆盖层退场并在浮箔中打开，保持主目录授权到目标箔片装载结束；不可读、未下载或打开失败留在覆盖层内说明。授权面板展示期间覆盖层让出焦点并暂停键盘监听，结束后恢复并重新查询。

## 15. 主目录范围下的“超时”修复（2026-09-24）

实机反馈：主目录范围下文件搜索经常显示“文件搜索超时”。用与 App 相同 entitlements 的签名探针（主目录 scope、相同谓词/排序/过滤）复现并测量：

- `mahler7` 这类没有匹配的查询结果数为 0，系统收集要到约 4.5 s 才结束；旧实现 3 s 截止时没有可用文件就直接报超时，于是“没有匹配”被误报成超时。
- 主目录范围把 `~/Library` 也纳入索引，无关候选多、收集慢。把 `NOT (kMDItemPath BEGINSWITH "<主目录>/Library/")` 加进谓词后：`mahler` 的收集从 5.4 s 缩短到 2.7 s，`报告` 2.7 s 完成，`test` 从 8.4 s 缩短到 7.0 s。

本轮调整：

- 谓词层排除 `~/Library`（代码侧 `isHomeLibrary` 过滤保留为兜底）。
- 截止改为两段：3 s 到点时已有可用文件就用当前结果结束；一个可用文件都没有时继续等待收集完成，最多到 10 s 兜底上限，仍未结束才报超时。这样“没有匹配”会正常显示“主目录中没有匹配的文件”。
- 回归：新增“收集晚于截止的空查询按空结果处理”，更新“未完成的空查询仍报超时”；定向与全量单元测试通过。
- 真机确认：`mahler7` 现在显示“主目录中没有匹配的文件。”，不再显示超时。
